iCode Workbench · Open-source agent development environment

A control room for a fleet of CLI agents.

iCode Workbench runs Claude Code, Codex, OpenCode, and 40+ more CLI agents in parallel, each in its own Git worktree. Queue durable tasks, review changes where the agent worked, manage any session from its own row, and keep terminals alive when the app restarts — while Mira watches every repository and tells you what needs you.

The workbench

One environment, from first prompt to reviewed change.

Sidebar

One sidebar for the whole portfolio.

Pinned projects, direct sessions grouped by worktree, the cross-project task queue, and live counts share one sidebar. Every row opens its own menu: a session row carries details, sleep or wake, restart, pin, and remove without switching to it first.

Harnesses

44 CLI agents, one workbench.

Claude Code, Codex, and OpenCode get native provider injection and Mira's native conversation. 21 harnesses have managed status hooks. 44 are launchable — from GitHub Copilot and Gemini to Cursor, Cline, Aider, Goose, Qwen Code, and more.

Isolation

Every session gets its own worktree.

A new session starts on its own branch at the current HEAD, so two agents in the same repository never edit the same checkout. Sleep a direct session to stop the process while keeping the checkout and resume token; wake it to continue where the harness supports it.

Terminals

The process outlives the window.

A detached host owns the PTYs, terminal emulation, and exit truth. Closing the window or quitting the app does not stop a live session; reopening reattaches to the same PTY with its scrollback and alternate-screen state intact. Terminals follow the app appearance, with a light ANSI palette on the light canvas.

Tasks

Durable work, not terminal tabs.

Queue tasks with a global 1–4 slot limit. They move through queued, dispatching, running, waiting, completed, failed, and cancelled. A retry is a new attempt; a review decision is separate from process exit. Schedules create ordinary queued tasks on a cadence.

Review

Review where the agent worked.

Files, Search, and Source Control share the persistent inspector, and the task workbench gives Files and Source Control full-width tabs. Changes are scoped to the session checkout: stage, inspect inline diffs, send line notes back to the agent, and commit, amend, push, cherry-pick, revert, or reset.

Editing

Edit in the same checkout.

Open Files beside the terminal and work in the same worktree the agent is editing. Explore, rename, duplicate, move, and search; Monaco adds editing, quick diffs against HEAD, inline blame, and file history.

Mira · Cross-project assistant

She watches all of it. You keep the decisions.

Mira is a person in the sidebar, not another project tab. One conversation spans every repository, and her answers come from the real projects, tasks, sessions, diffs, and review state.

  • She can act. Through validated actions she creates, cancels, retries, and archives tasks, messages task sessions and project supervisors, and records non-binding review recommendations.
  • She is bounded. She has no shell and no project working directory. She cannot approve a proposal, decide a review, merge, push, or edit project code.
  • She comes to you. Approvals, failures, waiting tasks, and review-ready work become proactive messages with a sidebar badge and an OS notification when no window is focused. Deduplication, an hourly budget, and quiet hours keep it from becoming noise.

In practice

See the task, then see the change.

Session lifecycle

Manage the session without opening it.

Details, sleep or wake, restart, pin, and remove are one right-click away. Lifecycle actions target the row's session even when another session is on screen, and an unavailable action explains why. If uncommitted or unmerged work is at risk, removal names the files or the retained branch and keeps the branch — there is no name to copy or type.

Schedules

Recurring work joins the same queue.

Schedules create ordinary queued tasks on a cadence — once, daily, weekdays, weekly, or every few hours — with queue-or-skip overlap handling and run-now. Pausing a schedule leaves tasks already created untouched, and every occurrence lands in the same task queue as work you queued by hand.

Availability

Available now, before 1.0.

iCode Workbench is pre-1.0 and ships as an unsigned build. CI produces Linux x64, Windows x64, and macOS x64 / arm64 packages for every tagged release, and the installers are published on GitHub Releases. Windows SmartScreen and macOS Gatekeeper warn on first launch; on macOS, right-click the app and choose Open. The source is public under AGPL-3.0-only, and a modified version offered to users over a network must provide them the corresponding source.

Download the latest release

Build from source. Requirements: Node 24.x (the repository pins 24.15.0), Corepack with pnpm 11.16.0, Git, and at least one harness on PATH. Linux also needs build-essential and python3; macOS needs Xcode Command Line Tools. 

git clone https://github.com/icodehq/icode-workbench.git
cd icode-workbench
corepack enable
pnpm install
pnpm dev

Then choose Add project, start a session, queue a task, or open Mira and ask what needs you.

Packaging details and platform notes are in the repository README. For the publicly available terminal agent, see iCode Agent.

Current limits, deliberately stated.

  • Managed status hooks cover 21 harnesses; harnesses without a hook stay unknown.
  • Mira’s streamed Markdown reply is Claude Code only. Codex and OpenCode show run stages and the final reply.
  • Tasks are supervised, not autonomous: a permission prompt still waits for a person.
  • Schedules are in-process timers and need iCode Workbench running.
  • Source Control is worktree-scoped; it does not manage stashes, tags, submodules, or arbitrary branch checkouts.
