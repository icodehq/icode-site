Claude Code in iCode Workbench

Claude Code is the CLI coding agent from Anthropic. In Workbench it runs as one of the primary harnesses: each session gets its own Git worktree, the task sits in a durable queue, and the diff is reviewed in the checkout where it was made.

This page is currently available in English only.

What Claude Code is good at

  • Long, tool-heavy tasks. Claude Code is designed for multi-step work: reading the repository, editing files, running commands, and iterating on failures.
  • Terminal-native workflow. It runs where your code runs, with your shell, your tools, and your credentials.
  • Anthropic models. Use your own Claude subscription or provider endpoint; Workbench does not replace the model or the agent loop.

Workbench does not change how Claude Code edits or compacts. It changes where the session runs, how the task is tracked, and how the result is reviewed.

Why run it in Workbench

  • One worktree per session. Two Claude Code sessions in one checkout can overwrite each other; Workbench gives each its own branch and working directory.
  • A durable queue. A session is a process; a task has states. Workbench tracks queued, running, waiting, completed, and failed work.
  • Native provider injection. Claude Code is one of the three harnesses (with Codex and OpenCode) that support provider endpoint injection and Mira's native assistant.
  • Review in place. Files, Search, and Source Control live beside the terminal, scoped to the session checkout, with line notes and a separate review decision.

Setup

  1. Install Claude Code using its official instructions, then confirm claude --version works in your shell.
  2. Run it once in a repository outside Workbench, so the CLI's own authentication and settings are in place.
  3. Add the repository to Workbench and open it. No model configuration is required to start; the harness keeps its own credentials.

If Claude Code is installed but Workbench does not see it, check that the claude executable is on the PATH of the shell Workbench launches. On Windows, a WSL target needs Claude Code installed inside the distro, not only on Windows.

Launch and resume

Create a new session from New worktree, choose Claude Code, and give the task a scope. Workbench launches claude in the session checkout. Each session is independent: its own branch, its own terminal, its own context.

Workbench uses Claude Code's resume recipe: --resume $TOKEN when a session id was captured, and --continue as the fallback. If the app restarts, the detached host keeps the PTY alive; sleep a session to stop the process and keep the checkout, then wake it to resume where the harness supports it.

Task and review

Give the session a task statement with a goal, owned paths, a done-when command, and an out-of-scope list. The statement is what makes the review possible; without it, you are judging a diff against nothing.

When the session finishes, review the diff in its checkout. Run the done-when command yourself, check files outside the owned paths, and decide: accept, revise, or reject. A completed process is not an accepted task.

Status at a glance

The session row shows the project, branch, target, and state. Claude Code reports its running and waiting state through Workbench's native adapter; a session that cannot report stays unknown rather than guessing. Sleep a session to stop the process and keep the checkout; wake it to resume where the harness supports it.

A concrete task

Task: “Fix token refresh when the API returns 401.”

  1. Create a worktree from main and name the branch after the task, not the agent.
  2. Scope the session: owned paths src/auth/** and tests/auth/**; route tables and public types are out of scope.
  3. Launch Claude Code in the session checkout and give it the task statement, including the done-when command.
  4. Queue the task if you have other work waiting; a slot limit of 1 is enough for the first run.
  5. Review the diff in the checkout: run the auth tests, check for a skipped test, and look for changes outside the owned paths.
  6. Decide accept, revise, or reject; merge only after the combined result passes.

The agent's summary is not the review. The diff, the tests, and the caller context are. If you want a second opinion, run the same task with another harness in its own worktree and compare the diffs; do not share a checkout.

Limits

  • Workbench does not change the agent. Claude Code's model behavior, context management, and tool permissions are its own.
  • Desktop only. Workbench is a desktop app; there is no mobile or remote server. If you need those, Orca is the broader tool.
  • Pre-1.0. Workbench is still changing; verify current behavior before standardizing a team on it.
