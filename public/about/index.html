About

iCode.

iCode builds the agent development environment — tools that put coding agents to work without taking the judgment away from the people doing the work.

What we do

We build products, not demos. Each one is designed to be used every day, to respect your machine, and to explain what it is doing. We ship when a product is ready rather than announcing a roadmap.

Both of our products are pre-1.0. They are usable today, and they change quickly; the honest boundaries are documented rather than hidden.

Products

Desktop · ADE · Early access

iCode Workbench

The control room for a team of coding agents. Claude Code, Codex, and OpenCode run in parallel, each in its own Git worktree. Tasks, approvals, schedules, review, and an editor live beside the terminal, and a detached host keeps sessions alive across app restarts.

Mira spans every project: she answers “what needs me?”, brings blockers to you, and acts through validated, bounded actions. Review, merge, and push remain human decisions.

Terminal · CLI

iCode Agent

A focused terminal coding agent that works directly in your repository. It reads the code, makes changes, runs your commands, and verifies its own work.

Its central discipline is context management. Long tasks are the hard case: the window fills, the agent loses the thread, and every request costs more. iCode Agent manages context at every boundary so long sessions stay coherent and affordable.

What stays constant

  • Local-first. Workbench keeps its state in local SQLite and adds no telemetry; Agent runs in your terminal and sends model traffic only to the endpoint you configure. Neither is a hosted service.
  • Your models. Workbench orchestrates the harnesses you already use. Agent speaks the openai and anthropic protocols. Model traffic goes to the endpoint you configure.
  • Human judgment. Agents can propose, change, and verify. A person still decides what to accept, merge, or ship.
  • Open source. Workbench is AGPL-3.0-only; Agent is Apache-2.0.
