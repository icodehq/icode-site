How releases work

iCode Workbench is pre-1.0 and follows semantic versioning. Each release is cut from a tagged commit; installers are attached to the GitHub release. Stable tags publish as normal releases; prerelease tags publish as GitHub prereleases so they do not become latest for stable clients.

Packaged builds check for updates shortly after launch and every six hours; the check can be disabled in Settings → Updates. Windows NSIS and packaged AppImage builds download on request and install after a restart. The first build with in-app updates still needs one manual install.

0.27.0 — 2026-11-24

  • Sessions repair their own workspaces. Opening or retrying a session probes its checkout with filesystem evidence, rebuilds a lost Git registration or index when safe, and recreates a missing checkout from its branch; a background sweep repairs the rest without blocking the window.
  • A plain recovery panel. A session that cannot be repaired shows Try again, Remove session, and Start fresh (keep old files); the old directory is moved beside the new one, never deleted.
  • Four session states. The sidebar, header, and details now say Starting, Running, Stopped, and Needs attention; worktree, host, branch, and path vocabulary moved behind Technical details.
  • Copy diagnostics. Paths, branches, baselines, host authority, and raw errors sit behind a collapsed Technical details section with a Copy diagnostics button.
  • Fewer false failures. A host or PTY startup failure no longer marks the checkout failed, and the redundant Check host action is gone.
  • Long Windows paths. Worktree Git commands pass core.longpaths, so deep checkouts under %APPDATA% are less likely to fail.

0.26.1 — 2026-11-24

  • Worktree row actions. Right-clicking anywhere on a worktree row opens Worktree actions; before, only the branch label answered the right-click.
  • Pointer cursor. Controls that answer a click now show the hand cursor; disabled controls and drag handles keep their own cursors.

0.26.0 — 2026-11-24

  • Large monorepos no longer freeze the window. Generated directories are skipped at any depth, so a package-level node_modules no longer creates tens of thousands of watchers.
  • WSL checkouts use polling. Files and Source Control no longer watch a WSL repository through Windows; they use the existing two-second polling fallback.
  • Watchers run outside the main process. A dedicated watcher child owns every physical watch; a crash or failed subscription falls back to polling instead of stalling the window.
  • Native recursive watching. Local watches prefer the operating system's native watcher and prune generated directories; chokidar remains an automatic fallback.
  • Files watches only visible directories. Collapsed folders drop their watch, reducing descriptor pressure.

0.25.0 — 2026-11-23

  • Updates unblocked. Historical unavailable sessions no longer block an install; only a session whose own host cannot prove its state does.
  • Update downloads follow the proxy. A proxy configured inside iCode now applies to electron-updater's own network session.
  • Timeouts and cancel. A stalled check or download no longer leaves the app in checking forever; the banner offers Cancel while downloading.
  • Install errors surfaced. The backend verifies the installer exists and records the attempt; failures show their session/process detail.
  • Packaged update E2E. CI can install an older build, serve the new installer, and verify the relaunched version.

0.24.0 — 2026-11-23

  • Resizable Projects and Tasks panes. Drag the seam to set the Tasks height; double-click to return to content-sized; the height survives a relaunch.
  • Project groups start collapsed. Expand a project with its chevron; expansion is remembered while the window runs.

0.23.1 — 2026-11-23

  • WSL responsiveness. Source Control, Files, and checkout resolution share guest calls instead of spawning one wsl.exe per request; the steady-state poll drops below one spawn per second.

0.23.0 — 2026-11-23

  • In-app updates. iCode checks the release feed shortly after launch and every six hours; Windows NSIS and packaged AppImage builds download on request and install after a restart.
  • Restart safety. Restarting asks before ending live sessions, sleeps them first, and stops the detached host and WSL holders so the installer can replace the app.
